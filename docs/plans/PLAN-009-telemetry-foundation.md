## 1. 목표
기존 게임 통계를 재사용하되 이벤트 중복, 판 단위 혼동, 시간 오측정, 전송 누락을 구분할 수 있는 기반을 단계별로 만든다. 한 단계의 검증을 마친 뒤 다음 단계로 진행한다.

## 2. 범위
- 포함: 이벤트 식별, 플레이 단위와 시간 정의, 판별 요약, 전송 신뢰성.
- 제외: GA4/Sentry SDK, 가입 UI, 원격 마이그레이션과 배포, 게임 규칙 및 점수 변경.
- 사용자 진행 요청으로 현재 실행 범위는 Step 3다. Step 4와 다른 플랜은 후속으로 남긴다.

## 3. 착수 당시 상태 / 전제
- EventLogger는 Supabase game_events로 20건 또는 5초마다 전송한다. 최대 200건 메모리 큐, 사용자당 분당 300건 서버 제한.
- session_id는 앱 실행 동안 고정이고 round_id와 클라이언트 event_id가 없다. 서버 id는 삽입마다 생성된다.
- params는 기존 스칼라 12개, 문자열 64자 제한이며 DB jsonb 크기는 2048바이트 이하다.
- duration_s는 벽시계 경과이며 활성 플레이 시간이 아니다. 레벨 전환과 이어하기의 종료 단위도 구분이 필요하다.
- MatchBoardGameStats와 로컬 PlayerRecords는 재사용한다. 기존 오디오 수정과 사용자 문서 변경을 보존한다.

## 9. Step 2 착수용 코드 조사 (2026-09-29)

Orca 읽기 전용 조사: `tmp/observability-plan-20260929/lifecycle-audit.md`. 보고서는 현재 소스의 위치와 회귀 테스트 후보를 담으며 구현 완료가 아니다.

- 현재 레벨 모드는 런 진입 시 round_start만 있고 레벨 클리어에는 level_clear만 있다. 다음 레벨에는 round_start가 없다. 이어하기 후 다시 시간 종료되면 round_end가 추가된다.
- 권장 계약: run_id + round_seq + attempt_seq로 구분하고 판별 round_start, 시도별 round_end를 정의한다. 종료 이벤트를 단순 합산하지 않고 판의 최종 시도를 따로 집계한다. 의미 변경은 schema_version을 올린다. Step 2 구현 전에 이벤트 표를 확정한다.
- 기존 _stageAttemptSerial은 광고 보상 키에도 쓰이므로 의미를 바꾸지 않는다. 관측용 순번은 별도로 둔다.
- EventLogger.instance가 static final이라 게임 이벤트를 테스트에서 관찰하기 어렵다. 최소 주입 지점을 먼저 마련한다.
- 비동기 랭킹 응답은 요청 시점 판 문맥을 캡처한다. 전역 현재 판 문맥만 읽으면 늦은 응답이 다음 판에 잘못 귀속될 수 있다.
- Last Hurrah 자동 제거가 기존 제거/특수 발동 통계에 포함된다. 사용자 직접 행동과 자동 마무리를 분리하거나 지표 정의에 포함 여부를 표시한다.
- 웹 뒤로가기의 종료/로컬 기록 누락 가능성은 코드상 가설이며 실제 웹 검증이 필요하다. 확인 없이 dispose에 기록 반영을 추가하지 않는다.
- 병렬 Wave: 2A 로거 문맥/테스트 주입과 2B 순수 시간 누적기 → 2C 게임/화면 연결 → 2D 독립 검수. 게임 배선과 공통 로거 동시 편집을 피한다.

## 11. Step 2 실행 계약 (2026-09-29)

- 현재 상태: Step 2 구현, 독립 검수, 최종 검증 완료. 다음은 Step 3 판별 요약과 행동 측정이다. 진행 표시: `PLAN-009 기존 게임 통계 기반 보강 → Step 2 판 구분과 시간 측정`.
- 식별 계약: 불변 PlayEventContext(run_id UUID, round_seq 1부터, attempt_seq 0부터)를 명시적으로 전달한다. 전역 현재 판 문맥은 두지 않는다. 모드 진입과 다시 하기는 새 run_id, 다음 레벨은 같은 run_id의 round_seq 증가, 광고 이어하기는 같은 판의 attempt_seq 증가다. round_id/attempt_id는 이 조합으로 식별하며 중복 UUID 필드는 만들지 않는다.
- 의미 변경을 schema_version 2로 구분한다. 문맥은 사용자 필드 12개와 별도 예약 필드로 계산하며 Step 1의 보호와 크기 제한을 유지한다.
- round_start는 판 시작마다 한 번, round_end는 시도 종료마다 한 번이다. level_clear도 종료에 포함하고 기존 level_clear 이벤트는 유지한다. 이어하기는 stage_continue로 새 시도를 표시한다. 점수는 시도별 누적 값이므로 합산하지 않는다.
- 시간 계약: Stopwatch 기반 단조 시계를 주입 가능한 순수 누적기로 사용한다. 프레임 dt 합산과 벽시계를 혼합하지 않는다. active/system/paused/background 중 한 상태만 누적한다. background 우선, 인트로와 Last Hurrah는 system, 메뉴/도움말/랭킹/NoMoves/결과/광고는 paused다. 아이템 확인/프리즘 선택은 게임 시계가 멈춰도 사용자 조작 가능하므로 active다. inactive는 기존 게임 동작을 유지한다.
- duration_s는 해당 판 시작부터 경과이며 active_s + system_s + paused_s + background_s와 일치한다(표시 반올림 오차 제외). 이어하기 뒤 종료는 같은 판 시작 기준 누적 시간이고, 다음 레벨은 초기화한다. 결과 대기와 광고 시간은 이어하기가 있을 때 다음 종료의 paused/background에 포함된다.
- 랭킹/광고 비동기 작업은 요청 전에 판 문맥을 캡처한다. 뒤늦은 응답이 다음 시도나 새 판에 귀속되면 안 된다.
- 로컬 RecordsStore 차감 계약, 광고 보상 키 _stageAttemptSerial, 게임 점수/타이머, 랭킹 제출 시점은 보존한다. 브라우저 강제 이탈에 새 종료/기록 처리는 넣지 않는다.
- 2B 완료 후 조회 시각 역행 방어를 추가로 발견해 2C에 RoundTiming과 해당 회귀 테스트의 수정 소유권을 넘겼다.
- 2A 소유: EventLogger, PlayEventContext, 관련 로거 테스트. 2B 소유: RoundTiming과 단위 테스트. 둘은 병렬. 완료 후 2C 소유: 게임/오버레이/랭킹/기록 연결과 회귀 테스트. 조정자는 문서와 최종 통합 검증. 2D는 읽기 전용 독립 검수, 수정은 구현 작업자에게 돌린다.
