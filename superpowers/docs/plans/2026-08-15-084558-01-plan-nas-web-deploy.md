# Stone Match NAS 웹 배포

**Goal:** 현재 `main`을 광고 없는 일반 Wasm 웹으로 빌드해 NAS `/match/`에 배포한다.
**Why planning is required:** 공개 NAS 서비스 상태를 변경하고 기존 원격 웹 번들을 교체한다.
**Acceptance:** 배포 전 `main`이 원격과 동기화된 깨끗한 상태이고 `.env`의 배포 설정이 존재해야 한다. 저장소의 `tools/deploy_match_web.sh`만 사용하며 업로드가 HTTP 200이 아니면 실패로 중단한다. 배포 후 공개 진입점과 핵심 정적 파일이 HTTP 200이고, `/match/` base href와 Wasm 격리 헤더가 맞으며 `match.zip`은 공개되지 않아야 한다. 실패 시 직전 정상 Git 리비전에서 같은 스크립트를 재실행할 수 있도록 앱인토스 AIT와 Git 상태를 보존한다. 토큰 값은 로그와 문서에 남기지 않는다.

### Outcome 1: 배포 대상 고정
- Work: 현재 `main`의 Flutter 소스만 `/match/`용 일반 Web으로 빌드하고 Apps in Toss 광고 브리지와 AIT를 포함하지 않는다.
- Verify: `git rev-list --left-right --count main...origin/main`, `git status --short --branch`

### Outcome 2: NAS 배포
- Work: 기존 배포 스크립트가 `build/web`, `match`, `match.zip`을 새로 만들고 설정된 NAS 엔드포인트에 업로드한다. 앱인토스 `stonematch.ait`는 보존한다.
- Risks/open questions: 서버 측 자동 백업은 확인되지 않았다. 업로드 실패나 원격 검증 실패 시 추가 변경 없이 중단한다.
- Verify: `tools/deploy_match_web.sh`

### Outcome 3: 원격 상태 검증
- Work: 공개 진입점, 핵심 번들, Wasm MIME 및 격리 헤더, ZIP 비공개 상태를 확인하고 로컬과 원격 핵심 파일 해시를 비교한다.
- Verify: `curl -I https://cheng80.myqnapcloud.com/match/`

## 실행 결과

- 일반 Wasm 웹 빌드와 `match.zip` 생성은 성공했다.
- NAS 업로드는 서버 443 포트 연결 시간 초과로 실패했다. HTTP 요청 전에 실패해 이번 시도에서는 원격 파일을 변경하지 않았다.
- 공개 `/match/` URL도 두 차례 같은 연결 시간 초과가 발생해 원격 상태는 검증하지 못했다.
- 로컬 `match/`, `match.zip`, 앱인토스 `stonematch.ait`는 보존했다. NAS 443 포트가 다시 연결되면 같은 배포 스크립트로 재시도한다.

### 재시도 결과

- NAS 연결 복구 후 같은 배포 스크립트를 재실행해 업로드 HTTP 200을 확인했다.
- 원격 `index.html`, `flutter_bootstrap.js`, `main.dart.wasm`의 SHA-256이 로컬 파일과 모두 일치했다.
- 공개 `/match/`와 `/match/game`은 HTTP 200, `main.dart.wasm`은 `application/wasm`, 격리 헤더 3종은 정상이며 `/match.zip`은 HTTP 404다.
- 브라우저에서 Stone Match 타이틀과 무한 모드 게임 보드 진입을 확인했고 콘솔 오류와 광고 표시는 없었다.
- 앱인토스 `stonematch.ait`는 변경되지 않았다.
