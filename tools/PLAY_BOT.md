# Stone Match 플레이 자동화

타임 모드에서 화면의 보석 색을 읽고 유효한 인접 교환을 실제 포인터로 실행한다. 기본 목표인 최대 8회 성공 후 자연스럽게 시간이 끝날 때까지 기다리고, 종료 점수가 양수인지 확인한다. 점수나 시간을 직접 바꾸지 않는다.

코드 위치, 원본 패키지, 과거 보고서와 종료 캡처는 [Flame 플레이 봇 자료](../docs/qa/play-bot/README.md)에 정리돼 있다. 과거 결과는 현재 빌드의 통과 근거로 사용하지 않는다.

## 에고에서 실행

```sh
npm install
npm run test:play-bot
# 미리 실행한 로컬/QA 서버의 게임 루트 URL을 지정한다.
npm run play:bot:ego -- --url http://127.0.0.1:8765/ --out tmp/play-bot/ego
```

한국어 게임 UI에서 1판 실행한다. `ego-browser`가 PATH에 있어야 한다. 다른 위치이면 `EGO_BROWSER_CLI`로 실행 파일을 지정한다. 출력된 TaskSpace ID를 기록한다. 중단된 작업은 사용자 제어 반환 후 같은 ID로 재개한다.

```sh
npm run play:bot:ego -- --space 3 --url http://127.0.0.1:8765/ --out tmp/play-bot/ego
```

`--space 3`은 실제 출력된 ID로 바꾼다. 같은 공간을 사용하더라도 스크립트는 대상 URL로 다시 이동하므로 이전 판의 중단 지점 복원을 보장하지 않는다. 에고 실행기는 URL을 생략하면 운영 NAS를 사용하므로 일반 회귀 실행에는 로컬/QA URL을 명시한다. 에고 경로는 `--qa`, QA query/hash와 GA4 응답 수집 옵션을 제공하지 않는다. 로컬/QA에서도 화면 인식으로 검증한다.

에고에서는 기존 사용 통계 설정을 유지한다. 운영 분석 검증 전에 설정의 "사용 통계 보내기"를 켜고 기록한다. 활성 에고 공간이 아닌 상태나 사용자 제어 전환은 우회하지 않는다. 성공하면 에이전트가 만든 테스트 공간만 닫고 기존 사용자 탭은 보존한다. 실패하면 공간과 보고서를 보존한다. 기본 네이티브 마우스 래퍼로 교환할 때 게임 일시정지가 관찰되어, 에고 봇은 `page.cdp('Input.dispatchMouseEvent', ...)`로 드래그를 전달한다. 게임의 일반 Flutter/Flame 입력과 매치 해소 경로를 사용하며 점수나 보드를 직접 변경하지 않는다.

## 별도 브라우저에서 반복 검증

현재 프로젝트의 브라우저 검증 기본은 에고다. 아래는 별도 브라우저 사용을 지정한 작업에서 이용하는 기존 실행 경로다.

```sh
# 로컬/QA 검증: 기존 QA 브리지로 점수와 보드 변화 확인
npm run play:bot -- --url http://127.0.0.1:8765/ --qa --out tmp/play-bot/qa

# 명시적으로 요청된 운영 수집 검증: 화면 인식, 분석 동의, GA4 응답 확인
npm run play:bot -- --url https://cheng80.myqnapcloud.com/match/ --analytics --rounds 2 --out tmp/play-bot/production
```

`package.json`은 검증한 `playwright-core` 1.63.0과 `pngjs` 7.0.0을 고정한다. `playwright-core`에 맞는 Chromium이 필요하다. 기존 설치가 없으면 `npx --package=playwright@1.63.0 playwright install chromium`으로 설치하거나 `--executable`로 사용할 브라우저 실행 파일을 지정한다. `--headed`는 화면을 표시한다. `--moves 1..20`으로 판당 교환 상한을 조절한다. 이 경로는 에고의 사용자 프로필과 별도인 임시 컨텍스트를 사용한다. `--analytics` 없이 실행하면 해당 임시 컨텍스트의 분석 동의는 꺼 둔다.

`--qa`와 `--analytics`를 함께 사용하지 않는다. `qaPerf=1`은 telemetry를 QA로 분류하며 운영 속성 검증에 사용할 수 없다. 일반 테스트 요청에는 로컬/QA URL을 사용한다. 운영 게임의 정상 플레이는 게임 자체의 이벤트와 랭킹 기록을 남길 수 있으므로 대상 환경을 보고서에 명시한다.

## 성공 기준과 보고서

- 안정된 화면 2장을 비교해 낙하/연쇄 중 입력을 피한다. 보석 최소 56칸이 읽힐 때만 알려진 색의 교환을 찾으며 미인식 칸은 매치나 교환에 사용하지 않는다.
- 실제 드래그 후 보드가 바뀌어야 성공 교환으로 센다. QA 경로는 점수 증가도 확인한다. 종료 문구 이후 최소 3초를 기다리고 1초 동안 같은 점수가 유지되어야 최종값으로 기록한다. 결과창의 양수 점수까지 확인해야 실행을 성공 처리한다.
- 현재 성공 판정은 유효 교환 1회 이상과 양수 종료 점수다. 기본 목표 8회를 모두 채웠는지는 `verifiedMoves`로 별도 확인한다. 별도 브라우저의 `errors`도 확인한다. `success=true`가 콘솔/네트워크 오류 전체의 부재를 보장하지 않는다.
- 같은 보드의 교환이 반복 실패하거나, 종료 제한 시간 150초를 넘거나, 에고가 반복해서 일시정지하면 성공으로 처리하지 않는다. 에고에서는 에이전트 소유 공간의 게임 자동 일시정지만 최대 3회 재개한다.
- `--analytics`는 운영 측정 ID `G-1D8SDVLZQX`의 `page_view`, `level_start`, `level_end`에 성공 HTTP 응답이 있는지 확인한다. 내부 `round_start`/`round_end`가 GA4에서는 `level_start`/`level_end`로 매핑된다. 내부 `session_start`는 직접 보내지 않고 Google이 GA4 세션을 생성한다.
- 수집 HTTP 응답과 GA4 보고서 반영은 별도다. 운영 수집 요청은 대시보드 production 최근 30분 진단까지 확인한다. 대시보드가 최대 15분 캐시하며 완료일 보고서는 처리 지연이 있을 수 있다.

출력 폴더의 `report.json`에 교환 시도/성공 수, 종료 점수, 실행 성공 여부와 오류를 기록한다. 별도 브라우저의 수집 로그에는 측정 ID, 이벤트 이름, HTTP 상태만 저장한다. 쿠키, client ID, 사용자 ID, 관리자 토큰은 저장하지 않는다. 플레이 및 종료 PNG도 보존한다.

보드 좌표는 현재 `PhoneFrame` 390×750과 `MatchBoardGameLayout` 타임 모드 계산을 따른다. UI 레이아웃이나 보석 팔레트가 바뀌면 `play_bot_vision.mjs`와 실제 플레이 검증을 함께 갱신한다. 이 봇은 타임 모드 전용이며 레벨/인벤토리/광고/실기기 검증을 대신하지 않는다.

## 실행 옵션

| 실행기 | 옵션 | 기본값과 제약 |
|---|---|---|
| 공통 | `--url` | hash 없는 게임 루트. 별도 브라우저 기본 `http://127.0.0.1:8765/`, 에고 기본 운영 NAS |
| 공통 | `--out` | 별도 브라우저 `tmp/play-bot/latest`, 에고 `tmp/play-bot/ego-latest`. 같은 폴더 재사용 시 이전 결과를 덮어쓰므로 실행별 폴더 사용 |
| 공통 | `--help` | 브라우저를 열지 않고 사용법 출력 |
| 에고 | `--space` | 기존 TaskSpace의 양의 정수 ID. 생략하면 새 테스트 공간 |
| 별도 브라우저 | `--rounds` | 기본 1, 허용 1 또는 2 |
| 별도 브라우저 | `--moves` | 기본 8, 허용 정수 1~20 |
| 별도 브라우저 | `--qa` | `qaPerf=1` 추가, 기존 읽기 브리지 사용. `--analytics`와 함께 사용 불가 |
| 별도 브라우저 | `--analytics` | 명시적 운영 수집 검증. 분석 동의 활성화와 필수 GA4 이벤트의 2xx 확인 |
| 별도 브라우저 | `--headed` | 기본 headless에서 화면 표시로 전환 |
| 별도 브라우저 | `--executable` | 설치된 브라우저 실행 파일 경로 |
| 별도 브라우저 | `--cdp` | 지정한 브라우저 CDP endpoint에 연결하되 새 컨텍스트를 사용. 종료 시 컨텍스트만 닫음 |

보고서 형식은 실행기에 따라 다르다. 별도 브라우저는 `rounds[]`, `ga4[]`, `errors[]`, `consent`를 기록하고, 에고는 최상위 `attempts`, `verifiedMoves`, `score`, `analyticsConsent`를 기록한다. 에고 동의 true만으로 GA4 수집 성공을 판정하지 않는다. 별도 브라우저의 `mode=production`은 `--qa`가 없다는 코드 분기 값이며 실제 배포 환경을 자동 확인한 값은 아니다.

## 실패 확인 순서

1. 대상 서버와 URL, 게임 언어를 확인한다. 에고는 한국어 메뉴를 사용한다. 서버 기동/빌드와 브라우저 설치는 봇이 대신하지 않는다.
2. 사용자 제어로 전환됐다면 중단한다. 제어 반환 뒤 기록한 TaskSpace ID를 사용한다.
3. 보드가 56칸 이상 읽히는지, 두 화면에서 안정됐는지, 실제 보드 변화가 있는지 확인한다. 동일 보드 교환 실패 또는 자동 일시정지 반복을 우회하지 않는다.
4. 종료 점수는 count-up이 끝난 값을 JSON과 종료 캡처에서 확인한다. 0점이나 시간 초과를 통과로 기록하지 않는다.
5. 운영 수집을 요청한 경우 동의와 필수 이벤트 HTTP 응답, 대시보드 조회 시각을 따로 확인한다. `ERR_ABORTED`가 함께 있으면 원문을 보존한다.

에고는 `current.png`, 첫 유효 교환의 `playing.png`, 성공 시 `end.png`와 `report.json`을 기록한다. 별도 브라우저는 `round-N-playing.png`, `round-N-end.png`, `report.json`을 기록하고 실패 처리 구간에서는 `failure-ui.txt`, `failure.png` 저장을 시도한다. 브라우저 시작이나 초기 설정 단계에서 실패하면 보고서가 없을 수 있으므로 명령의 종료 코드와 터미널 오류도 확인한다.
